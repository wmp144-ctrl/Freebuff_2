# مرحلهٔ ۲ — دیاگرام زندهٔ ارتباطات شبکه

این سند رفتار ماژول توپولوژی در مرحلهٔ ۲ را تعریف می‌کند: تبدیل دیاگرام
ترسیمی مرحلهٔ ۱ به نمایی زنده از وضعیت واقعی تجهیزات و لینک‌ها.

> اصل حاکم: **هیچ عدد یا رنگی ساختگی تولید نمی‌شود.** هر مقدار یا از نمونه‌های
> واقعی موتور مانیتورینگ می‌آید، یا از شمارندهٔ واقعی اینترفیس (SNMP)؛ اگر
> منبعی نباشد، «نامشخص/بدون سنجش» نمایش داده می‌شود.

---

## ۱. معماری

```
موتور مانیتورینگ (Ping/ICMP/TCP)
        │  devices + samples
        ▼
server/topology-live.js ──────────────┐
   وضعیت گره و لینک، jitter، کهنگی    │
        ▲                             ▼
        │                  GET /api/topology/diagrams/:id/status
server/link-telemetry.js              │
   سنجش اختیاری SNMP اینترفیس         ▼
        ▲                     بوم دیاگرام (رنگ، متریک، پنل بازرسی)
        │
server/snmp.js  (SNMPv2c داخلی، بدون وابستگی خارجی)
```

- ماژول مستقل است و فقط با پایگاه‌داده و allowlist پروب صحبت می‌کند.
- هیچ تغییری در منطق موتور Ping، هشدار یا Retention انجام نشده است.
- سنجش SNMP اختیاری است؛ نبود آن فقط باعث «بدون سنجش» شدن مصرف می‌شود.
- کل مسیر آفلاین است: UDP به شبکهٔ مدیریت محلی، بدون هیچ وابستگی اینترنتی.

## ۲. رنگ‌بندی و قواعد وضعیت

| رنگ | وضعیت | قاعده |
| --- | --- | --- |
| سبز | `up` | همهٔ منابع تازه‌اند، هیچ تجهیزی قطع/هشدار نیست، افت/تأخیر/نوسان زیر آستانه و اشغال زیر ۷۵٪ |
| قرمز | `down` | یکی از تجهیزات دو سر قطع است یا `ifOperStatus` در آخرین سنجش تازه SNMP پایین است |
| زرد | `degraded` | وضعیت هشدار تجهیز، افت بسته بیشتر از آستانه، تأخیر بیشتر از آستانه، نوسان بیشتر از ۴۰ms، یا اشغال ≥ ۷۵٪ |
| خاکستری | `unknown` | دادهٔ کهنه (بیش از ۳ بازهٔ پایش، حداقل ۹۰ ثانیه)، تجهیز در حال نگهداری، بدون منبع سنجش یا دادهٔ ناکافی |

قواعد تکمیلی:

- اگر یکی از دو سر دادهٔ تازه نداشته باشد، لینک **خاکستری** می‌شود؛ نمایش سبز
  یا زرد در این حالت قابل تأیید نیست.
- دادهٔ تجهیزِ غیرفعال‌شده از پایش (`monitoring_enabled = 0`) کهنه تلقی می‌شود.
- ترتیب اولویت: قطع اینترفیس SNMP ← نبود/کهنگی منبع ← قطع تجهیز ←
  کهنگی نسبی ← هشدار/آستانه‌ها ← اشغال ظرفیت ← سالم.
- رنگ لینک در بوم فقط از همین وضعیت می‌آید؛ رنگ دلخواه کاربر برای لینک در
  نمای زنده اعمال نمی‌شود تا معنای رنگ‌ها یکتا بماند (رنگ دلخواه در خروجی
  تصویری/حالت بدون داده حفظ می‌شود).

## ۳. متریک‌ها

| متریک | منبع | توضیح |
| --- | --- | --- |
| تأخیر (`latencyMs`) | آخرین RTT تجهیزات دو سر/تجهیز مرجع | بیشترین مقدار بین منابع تازه |
| افت بسته (`lossPct`) | `devices.loss_pct` همان منابع | بیشترین مقدار؛ آستانهٔ هر تجهیز یا تنظیمات عمومی |
| نوسان تأخیر (`jitterMs`) | میانگین قدرمطلق اختلاف نمونه‌های متوالی RTT | حداکثر ۱۰ نمونهٔ ۳۰ دقیقهٔ اخیر هر تجهیز |
| پهنای باند اسمی (`capacityMbps`) | مقدار ثبت‌شده روی لینک؛ در نبود آن `ifHighSpeed` | هرگز حدس زده نمی‌شود |
| مصرف لحظه‌ای (`rxMbps`/`txMbps`) | شمارندهٔ `ifHCInOctets`/`ifHCOutOctets` | اختلاف شمارندهٔ ۶۴بیتی در بازهٔ واقعی |
| اشغال ظرفیت (`utilPct`) | `max(rx,tx) / capacity` | فقط با سنجش تازه |
| وضعیت اشباع | ۷۵٪ هشدار، ۹۰٪ بحرانی | «پرترافیک» و «نزدیک اشباع» |

- شمارندهٔ اول فقط مبنای محاسبه است و مصرف نمایش داده نمی‌شود؛ از نمونهٔ دوم
  نرخ محاسبه می‌شود.
- ریست/سرریز شمارنده تشخیص داده می‌شود و نرخ ساختگی تولید نمی‌کند.
- سنجش قدیمی‌تر از ۳ بازهٔ سنجش (حداقل ۹۰ ثانیه) در وضعیت اثر ندارد، اما
  آخرین مقدار با برچسب «کهنه» در پنل دیده می‌شود.

---

## ۴. به‌روزرسانی خودکار

- صفحهٔ دیاگرام هر **۱۰ ثانیه** وضعیت را از `/status` می‌خواند (تب مخفی: متوقف).
- در صورت اتصال SSE، رویدادهای واقعی شبکه حداکثر هر ۴ ثانیه یک بازخوانی
  زودتر را Trigger می‌کنند.
- بازگشت به تب، بازخوانی فوری با `?fresh=1` انجام می‌دهد.
- کش سمت سرور حداکثر ۳ ثانیه است؛ N کاربر هم‌زمان باعث N بار محاسبه در هر
  ثانیه نمی‌شوند.
- وضعیت هرگز از سمت کلاینت قابل تغییر نیست؛ هیچ دکمهٔ «قطع/وصل» وجود ندارد.

## ۵. پیکربندی سنجش ترافیک (اختیاری)

پیش‌نیاز: تجهیز (سوئیچ/روتر) SNMPv2c فعال داشته باشد و آدرس سرور NetWatch در
ACL آن مجاز باشد.

1. روی لینک کلیک کنید و در پنل بازرسی:
   - **پهنای باند اسمی** را وارد کنید (Mbps) یا یکی از گزینه‌های آماده را بزنید.
   - **تجهیز مرجع سنجش** را انتخاب کنید (اختیاری؛ پیش‌فرض تجهیزات دو سر لینک).
   - **سنجش ترافیک اینترفیس (SNMP)** را روشن و `ifIndex` را وارد کنید.
     اگر «عامل SNMP» خالی بماند، IP تجهیز مرجع/دو سر لینک استفاده می‌شود.
2. دکمهٔ **سنجش فوری ترافیک** را بزنید. نتیجهٔ سنجش و خطاها در همان پنل دیده
   می‌شود؛ از آن پس زمان‌بند سراسری هر ۳۰ ثانیه لینک‌های فعال را می‌خواند.

`ifIndex` را از `snmpwalk <device> 1.3.6.1.2.1.2.2.1.2` یا پنل مدیریت سوئیچ
بردارید.

### متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `NETWATCH_SNMP_INTERVAL_SEC` | `30` | بازهٔ سنجش (۵ تا ۳۶۰۰) |
| `NETWATCH_SNMP_TIMEOUT_MS` | `2000` | مهلت هر درخواست |
| `NETWATCH_SNMP_PORT` | `161` | پورت عامل SNMP (برای آزمون/استقرار غیرمعمول) |
| `NETWATCH_SNMP_COMMUNITY` | `public` | community؛ فقط در فایل محیطی ۰۶۰۰ نگه دارید |
| `NETWATCH_SNMP_DISABLE` | `0` | `1` = خاموش‌کردن زمان‌بند (سنجش دستی باقی می‌ماند) |

نکته‌های امنیتی:

- مقصد SNMP از همان `probe_allowed_cidrs` عبور می‌کند؛ فقط IPv4 پذیرفته می‌شود.
- community در پایگاه‌داده، دیاگرام یا خروجی JSON ذخیره نمی‌شود.
- فقط نمونهٔ رهبر موتور سنجش می‌کند تا با چند نمونهٔ سرور، اینترفیس چندبار
  خوانده نشود.
- خطای SNMP هرگز به موتور Ping یا هشدارهای موجود سرریز نمی‌کند.

## ۶. API

| مسیر | توضیح |
| --- | --- |
| `GET /api/topology/diagrams/:id/status` | Snapshot زندهٔ گره‌ها/لینک‌ها + خلاصه؛ `?fresh=1` برای عبور از کش |
| `POST /api/topology/diagrams/:id/telemetry/poll` | سنجش فوری لینک‌های دارای SNMP و بازگرداندن Snapshot تازه |

نمونهٔ فیلدهای لینک در پاسخ:

```json
{
  "id": "…",
  "status": "degraded",
  "reasonCode": "saturation",
  "reason": "اشغال ظرفیت (۸۰٪) به آستانهٔ هشدار (۷۵٪) رسیده است.",
  "latencyMs": 24.2,
  "lossPct": 0,
  "jitterMs": 9.5,
  "capacityMbps": 100,
  "utilPct": 80,
  "rxMbps": 80,
  "txMbps": 4,
  "saturation": "high",
  "telemetryAt": 1790000000000,
  "telemetryStale": false,
  "operStatus": "up",
  "sourceCount": 2,
  "reportingCount": 2
}
```

## ۷. آزمون

```bash
# قواعد وضعیت، نوسان، اشباع
node --test server/tests/integration/topology-live.test.mjs

# کارخواه SNMP با عامل ساختگی محلی (بدون شبکهٔ بیرونی)
node --test server/tests/unit/snmp.test.mjs

# کمک‌تابع‌های نمایش
npm run test:web
```

آزمون یکپارچه یک عامل SNMP ساختگی محلی اجرا می‌کند، شمارنده‌ها را افزایش
می‌دهد و درصد اشغال، رنگ لینک و `interface-down` را بررسی می‌کند؛ بنابراین
مسیر واقعی «موتور → Snapshot → API → نمایش» پوشش داده می‌شود.

# واژه‌نامه و مفاهیم پایه

این فایل اصطلاحاتی را تعریف می‌کند که در سراسر مستندات NetWatch تکرار می‌شوند.
هدف این است که کاربر مبتدی بدون دانش قبلی بتواند ادامه دهد و توسعه‌دهنده نیز
معنای دقیق هر اصطلاح را در همین پروژه بداند.

> اصطلاحات در اولین استفاده در هر سند هم تعریف می‌شوند؛ این واژه‌نامه مرجع
> یکجای آن‌هاست.

---

## ۱. مفاهیم پایش شبکه

| اصطلاح | تعریف در NetWatch |
| --- | --- |
| **Ping** | ارسال بستهٔ ICMP Echo به یک میزبان و اندازه‌گیری زمان پاسخ. NetWatch در حالت `icmp` از فرمان سیستمی `ping` استفاده می‌کند. |
| **Probe** | یک «بررسی فعال» از سمت سرور به مقصد. در این پروژه هم Ping دستی، هم بررسی زنده و هم بررسی موتور را در بر می‌گیرد و تابع سیاست شبکه است. |
| **ICMP** | پروتکل پیام کنترل اینترنت؛ مبنای Ping سنتی. در لینوکس برای سوکت خام به مجوز `CAP_NET_RAW` نیاز دارد. |
| **TCP Ping** | اتصال به یک پورت TCP (پیش‌فرض ۸۰) و اندازه‌گیری زمان برقراری اتصال. جایگزین ICMP وقتی مجوز خام وجود ندارد. |
| **RTT** | Round-Trip Time؛ زمان رفت‌وبرگشت بسته بر حسب میلی‌ثانیه. |
| **Packet Loss** | درصد بسته‌های ارسال‌شده‌ای که پاسخ نگرفته‌اند. |
| **Availability** | نسبت بررسی‌های موفق به کل بررسی‌ها در یک بازه، به درصد. |
| **Uptime** | درصد دسترس‌پذیری تجهیز بر پایهٔ نمونه‌ها/آمار روزانه. |
| **Outage** | بازهٔ قطعی یک تجهیز؛ با `started_at` باز و با `ended_at` و `duration_sec` بسته می‌شود. |
| **Flap** | قطع و وصل مکرر و کوتاه یک تجهیز؛ در گزارش «نوسان» دیده می‌شود. |
| **Maintenance Window** | بازهٔ زمانبندی‌شده‌ای که بررسی یک تجهیز (یا همه) متوقف و وضعیت «تعمیرات» می‌شود. |
| **Health Score** | امتیاز ۰ تا ۱۰۰ داشبورد بر پایهٔ دسترس‌پذیری، نسبت آنلاین، تأخیر و افت بسته. |
| **MTTR** | میانگین زمان رفع قطعی. |
| **MTBF** | میانگین زمان بین دو خرابی. |

## ۲. اجزای نرم‌افزار

| اصطلاح | تعریف |
| --- | --- |
| **موتور (Engine)** | مؤلفه‌ای که تجهیزات سررسیدشده را انتخاب می‌کند، Probe می‌زند، نتیجه را ثبت می‌کند، قطعی/هشدار می‌سازد و آمار روزانه را تجمیع می‌کند. فایل اصلی: `server/engine.js`. |
| **engine-cli** | اجرای مستقل موتور بدون رابط کاربری؛ `server/engine-cli.js` با `npm run engine`. |
| **رهبر (Leader)** | تنها نمونه‌ای که اجازهٔ Probe و نوشتن نتیجه را دارد. با قفل `engine_lock` تعیین می‌شود. |
| **Fencing Token / epoch** | شمارندهٔ افزایشی مالکیت رهبری. نتیجه‌ای که با epoch قدیمی برگردد باطل می‌شود تا دادهٔ متناقض نوشته نشود. |
| **SSE** | Server-Sent Events؛ کانال یک‌طرفهٔ سرور به مرورگر روی `/api/events` برای نمونه‌ها، وضعیت و هشدارهای زنده. |
| **SPA** | Single Page Application؛ رابط React که در `web/dist` ساخته و توسط همان سرور سرو می‌شود. |
| **Job / Worker** | پردازش سنگین (Excel، MBTiles) در Worker Thread با صف و مهلت؛ فایل `server/jobs.js`. |
| **Manifest** | فایل `manifest.json` هر پشتیبان با نسخه، حجم، SHA-256 و تعداد رکوردها. |
| **Checkpoint** | انتقال محتوای WAL به فایل اصلی SQLite؛ در پشتیبان‌گیری و خاموشی مرتب اجرا می‌شود. |
| **WAL** | Write-Ahead Log؛ حالت ژورنال SQLite که خواندن و نوشتن هم‌زمان را ممکن می‌کند. |
| **Retention** | سیاست حذف دوره‌ای داده‌های قدیمی با تراکنش‌های کوچک و محافظت از دادهٔ تجمیع‌نشده. |
| **Legal Hold** | پرچم توقف کامل حذف داده برای الزام قانونی/قراردادی. |
| **Dry-Run** | اجرای آزمایشی که فقط شمارش می‌کند و هیچ داده‌ای را حذف یا تغییر نمی‌دهد. |
| **GFS** | Grandfather-Father-Son؛ سیاست نگهداری پشتیبان روزانه/هفتگی. |
| **RPO** | حداقل بازهٔ داده‌ای که ممکن است در خرابی از دست برود. |
| **RTO** | هدف زمانی بازگشت سرویس پس از خرابی. |
| **Seed Demo** | دادهٔ نمایشی اولیه (تجهیزات و تاریخچه) برای ارزیابی؛ با `NETWATCH_SEED_DEMO=0` خاموش می‌شود. |

## ۳. امنیت و دسترسی

| اصطلاح | تعریف |
| --- | --- |
| **RBAC** | کنترل دسترسی مبتنی بر نقش؛ سه نقش `admin`، `operator` و `viewer`. |
| **Permission** | مجوز ریزدانه به شکل `<منبع>:<کنش>` مثل `devices:write` یا `probe:run`. |
| **Session** | نشست ورود با کوکی `nw_session`؛ در پایگاه‌داده فقط هش SHA-256 توکن ذخیره می‌شود. |
| **CSRF** | Cross-Site Request Forgery؛ در این پروژه با الگوی double-submit و هدر `X-CSRF-Token` مهار می‌شود. |
| **Same-Origin** | گاردی که درخواست‌های تغییردهنده با `Origin` بیگانه را رد می‌کند. |
| **Argon2id** | الگوریتم هش رمز عبور با پارامترهای OWASP؛ رمز خام ذخیره نمی‌شود. |
| **Rate Limit** | سقف تعداد درخواست در بازهٔ زمانی، به تفکیک IP و حساب. |
| **CIDR** | نمایش بازهٔ آدرس IP؛ برای محدودکردن Probe و APIهای مدیریتی. |
| **Link-Local** | آدرس‌های `169.254.0.0/16` و `fe80::/10`؛ به‌طور پیش‌فرض برای Probe مسدودند. |
| **Metadata Endpoint** | سرویس‌های ابری روی `169.254.169.254` و مشابه؛ به‌طور پیش‌فرض مسدود. |
| **Audit Log** | گزارش فقط‌افزودنی تغییرات حساس با کاربر، IP، مسیر، نتیجه و جزئیات پاک‌سازی‌شده. |
| **HSTS** | هدر `Strict-Transport-Security` که مرورگر را به HTTPS ملزم می‌کند. |
| **CSP** | Content-Security-Policy؛ در حالت تولید اعمال می‌شود. |

## ۴. داده و گزارش

| اصطلاح | تعریف |
| --- | --- |
| **Sample** | یک نتیجهٔ Probe در جدول `samples` با زمان، RTT، افت، وضعیت و حالت. |
| **Daily Stats** | تجمیع روزانه در `daily_stats`؛ مبنای گزارش‌های بلندمدت پس از حذف نمونه‌های خام. |
| **Rollup** | محاسبه/به‌روزرسانی `daily_stats` از نمونه‌ها و قطعی‌ها. |
| **Alert Rule** | قاعدهٔ هشدار با نوع، دامنه، تأخیر، Cooldown و پرچم سکوت. |
| **Alert** | رکورد هشدار با وضعیت `active`/`acknowledged`/`resolved`/`suppressed`. |
| **Acknowledge** | تأیید دیدن هشدار توسط اپراتور، بدون رفع آن. |
| **Suppression** | سرکوب هشدار در بازهٔ سکوت؛ رکورد با وضعیت `suppressed` ذخیره می‌شود. |
| **MBTiles** | فایل SQLite شامل کاشی‌های نقشه برای نمایش آفلاین. |
| **Marker** | علامت دلخواه روی نقشه با نام، نوع و مختصات. |
| **API Contract** | شکل مورد انتظار پاسخ API که تایپ‌های فرانت و آزمون قرارداد بر آن تکیه دارند. |

## ۵. یکاها و قراردادهای عددی

| مورد | قرارداد |
| --- | --- |
| زمان | epoch milliseconds (UTC) در API و پایگاه‌داده |
| زمان‌بندی روزانه | بر پایهٔ `timezone_offset_minutes` (پیش‌فرض `210` برای Asia/Tehran) |
| تأخیر | میلی‌ثانیه (`ms`) |
| افت بسته | درصد (`0..100`) |
| دسترس‌پذیری | درصد (`0..100`) |
| حجم فایل | بایت در API؛ مگابایت/گیگابایت در متن مستندات |
| بازهٔ پایش | ثانیه |
| مهلت‌ها | میلی‌ثانیه |
| صفحه‌بندی | `page` از ۱ و `pageSize` با سقف‌های هر Endpoint |

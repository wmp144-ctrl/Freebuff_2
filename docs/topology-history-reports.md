# تاریخچه، مقایسه، بازگردانی و گزارش‌های دیاگرام ارتباطات

این سند مرحلهٔ ۴ ماژول دیاگرام ارتباطات NetWatch را توضیح می‌دهد. تمام داده‌ها از
پایگاه‌داده و وضعیت زندهٔ همان لحظه می‌آید؛ هیچ نسخه، تغییر یا عدد گزارشی در
سمت مرورگر یا سرور به‌صورت ساختگی تولید نمی‌شود.

---

## ۱. مدل تاریخچه

### چه زمانی نسخه ثبت می‌شود؟

| رویداد | `action` | توضیح |
| --- | --- | --- |
| ساخت دیاگرام | `create` | نسخهٔ اولیه، حتی اگر گراف خالی باشد |
| تکثیر/ساخت از الگو | `create` | نسخهٔ دیاگرام تازه با شناسه‌های مستقل |
| ذخیرهٔ گراف | `graph` | افزودن، حذف یا ویرایش گره/لینک، ظرفیت، سنجش، یادداشت و جابه‌جایی |
| تغییر مسیرها | `paths` | جایگزینی گروه‌های اصلی/پشتیبان |
| تغییر مشخصات | `metadata` | نام، توضیح، چیدمان، تنظیمات و قفل/بازکردن قفل |
| پیش از بازگردانی | `pre-restore` | وضعیت فعلی پیش از جایگزینی، برای امکان بازگشت |
| بازگردانی | `restore` | نسخهٔ حاصل از جایگزینی، با ارجاع به نسخهٔ مبدأ |
| نسخهٔ پایه | `baseline` | نخستین مشاهدهٔ تاریخچهٔ دیاگرام‌های قدیمی پیش از این مرحله |

جابه‌جایی دید (Viewport) به‌تنهایی نسخه نمی‌سازد؛ چون تغییر ساختاری نیست و
باعث تولید انبوه نسخه با هر Pan/Zoom می‌شد. ذخیرهٔ خودکار گراف همچنان هر
تغییر واقعی ساختار را ثبت می‌کند.

### محتوای هر نسخه

- Snapshot کامل و فشرده (gzip) از گره‌ها، لینک‌ها، مسیرها، نام، توضیح، چیدمان،
  تنظیمات و وضعیت قفل.
- شمارش خلاصه: گره، لینک، مسیر، تجهیز و مرکز.
- Diff ساختاری با نسخهٔ قبلی: افزودن/حذف/ویرایش گره، لینک و مسیر و
  تغییرات فیلد‌به‌فیلد.
- نویسنده (نام کاربری)، زمان، شمارهٔ `revision` گراف و نسخهٔ مبدأ در بازگردانی.

Snapshot به‌صورت BLOB فشرده ذخیره می‌شود. `changes` برای نمایش سریع مقایسه
است و شمارش‌های آن همیشه کامل‌اند؛ فهرست جزئیات برای جلوگیری از پاسخ‌های
بسیار بزرگ به ۲۰۰ مورد در هر دسته محدود می‌شود و `truncated` این محدودیت را
صریح اعلام می‌کند.

### نگهداری

حداکثر **۲۰۰ نسخهٔ آخر** هر دیاگرام نگهداری می‌شود. نسخه‌های قدیمی‌تر در
همان تراکنش ثبت نسخهٔ تازه حذف می‌شوند. این محدودیت در پاسخ API
(`retention`) و در پنل رابط کاربری نمایش داده می‌شود.

### مقایسه

مقایسه بر پایهٔ Snapshot دو نسخه انجام می‌شود، نه متن Diff ذخیره‌شده. بنابراین
مقایسهٔ هر دو نسخهٔ دلخواه و «وضعیت فعلی» همیشه با ساختار واقعی همان لحظه
سازگار است. فیلدهای مقایسه‌شده:

- گره: نوع، تجهیز/مرکز متصل، برچسب، یادداشت، موقعیت، ابعاد، رنگ، لایه و فراداده
- لینک: دو سر، نوع، برچسب، یادداشت، رنگ، سبک، ظرفیت، تجهیز مرجع، پیکربندی SNMP و فراداده
- مسیر: نام، نقش، دنبالهٔ گره‌ها و لینک‌ها
- مشخصات دیاگرام: نام، توضیح، چیدمان، تنظیمات و قفل

### بازگردانی

1. نسخهٔ مقصد و مالکیت آن نسبت به دیاگرام بررسی می‌شود.
2. اگر دیاگرام قفل باشد، بازگردانی با `423` رد می‌شود.
3. نسخهٔ «پیش از بازگردانی» از وضعیت فعلی ثبت می‌شود.
4. گره‌ها، لینک‌ها، مسیرها، مشخصات و قفل از Snapshot جایگزین می‌شوند.
5. شناسه‌های تجهیز/مرکز که در این فاصله حذف شده‌اند `NULL` می‌شوند تا ارجاع
   شکسته ساخته نشود؛ این موارد در `restoreWarnings` برمی‌گردند.
6. `revision` دیاگرام یک واحد افزایش می‌یابد و نسخهٔ `restore` با ارجاع به
   نسخهٔ مبدأ ثبت می‌شود.

بنابراین بازگردانی خودش هم قابل بازگشت است. سنجش ترافیک لینک‌ها پس از
بازگردانی پاک می‌شود تا با پیکربندی قدیمی/جدید اشتباه نشود و در چرخهٔ بعدی
دوباره خوانده شود.

## ۲. API

همهٔ مسیرها زیر `/api` و با مجوز `topology:read` (خواندن) یا
`topology:write` (تغییر) هستند.

| متد و مسیر | کار |
| --- | --- |
| `GET /topology/diagrams/:id/versions?limit=&before=` | فهرست نسخه‌ها با صفحه‌بندی؛ در صورت نبود نسخه، نسخهٔ پایه ساخته می‌شود |
| `GET /topology/diagrams/:id/versions/:versionId` | جزئیات کامل Snapshot و تغییرات همان نسخه |
| `GET /topology/diagrams/:id/versions/compare?a=&b=current` | مقایسهٔ دو نسخه؛ `b=current` وضعیت ذخیره‌شدهٔ فعلی |
| `POST /topology/diagrams/:id/versions/:versionId/restore` | بازگردانی؛ بدنهٔ اختیاری `{ revision }` برای جلوگیری از تعارض |
| `GET /topology/diagrams/:id/report` | گزارش ساختاریافتهٔ JSON |
| `GET /topology/diagrams/:id/report/export?format=xlsx` | خروجی Excel چندبرگی |
| `GET /topology/diagrams/:id/report/export?format=pdf` | خروجی PDF فارسی راست‌به‌چپ |

در صورت تعارض `revision` پاسخ `409` با شمارهٔ نسخهٔ سرور برمی‌گردد. خطاهای
قفل `423`، نسخهٔ ناموجود `404` و ورودی نامعتبر `400` هستند.

## ۳. گزارش‌ها

گزارش از `loadDiagram` (گراف و وضعیت زندهٔ لینک‌ها)، تعریف مسیرها و موتور
تحلیل مرحلهٔ ۳ ساخته می‌شود. بخش‌ها:

1. **ساختار کلی شبکه و توپولوژی:** تعداد گره/تجهیز/مرکز/ابر/لینک، مؤلفه‌های
   همبند، گره‌های بدون اتصال، میانگین درجه، توزیع نقش‌ها و انواع لینک.
2. **تجهیزات و مراکز تجمع:** فهرست تجهیزات متصل به دیاگرام با IP، نقش، وضعیت،
   مرکز/موقعیت، گروه و تعداد اتصال؛ فهرست مراکز با عضویت، آنلاین/آفلاین و
   حضور روی دیاگرام.
3. **مسیرهای اصلی و پشتیبان:** گروه‌ها، نقش، مبدأ/مقصد، تعداد گام، وضعیت
   مسیر، فعال/غیرفعال، مسیر شکسته و پشتیبان فعال.
4. **وضعیت لینک‌ها و اختلالات:** وضعیت چهارگانهٔ واقعی، دلیل، تأخیر، افت، نوسان
   و منبع سنجش. لینک بدون داده «نامشخص» است، نه سالم یا قطع.
5. **ظرفیت و میزان مصرف:** ظرفیت ثبت‌شده، درصد اشغال، دریافت/ارسال، دستهٔ بار،
   ظرفیت کل، میانگین وزنی مصرف و شمار لینک‌های بدون ظرفیت/سنجش.
6. **نقاط بحرانی و وابستگی:** تجهیزات برشی، لینک‌های تک‌مسیره (پل)، تجهیزات
   وابسته و رخدادهای فعال تا مرکز زیرساخت.

### PDF

- A4 افقی، فونت **Vazirmatn** توکار در `server/assets` (بدون نیاز به فونت نصب‌شده).
- ترتیب راست‌به‌چپ با `bidi-js` و کشیدن واژه‌به‌واژه؛ نام‌های لاتین و عددها
  جهت خودشان را حفظ می‌کنند.
- جدول‌ها سرستون تکرارشونده و شمارهٔ صفحه دارند.
- برای گراف‌های بسیار بزرگ، PDF حداکثر ۱۲۰۰ ردیف نخست هر جدول را نمایش
  می‌دهد و این محدودیت را در همان صفحه می‌نویسد؛ Excel کامل است.

### Excel

برگه‌های `خلاصه`، `ساختار`، `تجهیزات`، `مراکز تجمع`، `مسیرها`، `لینک‌ها`،
`ظرفیت و مصرف`، `نقاط بحرانی` و در صورت وجود `هشدارها`. جهت برگه‌ها RTL است و
مقادیر عددی به‌صورت عدد ذخیره می‌شوند.

## ۴. استفاده در رابط کاربری

در صفحهٔ «دیاگرام ارتباطات»، دکمهٔ **«تاریخچه و گزارش»** در نوار وضعیت زنده:

- **نسخه‌ها:** فهرست، جزئیات تغییرات و بازگردانی با تأیید.
- **مقایسه:** انتخاب «از نسخه» و «با نسخه/وضعیت فعلی» و نمایش تغییرات
  فیلد‌به‌فیلد.
- **گزارش‌ها:** نمایش خلاصهٔ ساختار، تجهیزات، مراکز، مسیرها، لینک‌ها، ظرفیت و
  ریسک‌ها، همراه با دکمه‌های دانلود PDF و Excel.

پیش از بازگردانی، تغییرات ذخیره‌نشدهٔ فعلی ذخیره می‌شوند؛ اگر ذخیره ناموفق
باشد بازگردانی انجام نمی‌شود تا داده از دست نرود.

## ۵. آزمون و وارسی

```bash
npm run lint
npm run typecheck
node --experimental-strip-types --test server/tests/integration/topology-history-report.test.mjs
npm run test:integration
```

آزمون یکپارچه، ثبت نسخه در ایجاد/ویرایش/مسیرها، Diff فیلد‌به‌فیلد، مقایسه،
بازگردانی همراه با بازگردانی مشخصات، خروجی Excel قابل خواندن با SheetJS و
خروجی PDF معتبر را بررسی می‌کند. نمایش PDF با موتور PDF و تصویرسازی
(`pymupdf`) در توسعه بررسی شده است.

## ۱. دامنهٔ این مرحله

این گزارش نتیجهٔ «بخش پنجم: تست نهایی، پایداری بلندمدت و آماده‌سازی انتشار» است.
تمرکز روی پوشش کامل Endpointها، نقش‌ها و ورودی مخرب، هم‌زمانی، Crash/Recovery،
بار ۱۰۰ تا ۵٬۰۰۰ تجهیز، ۱۰۰ اتصال SSE، ورود ۵۰٬۰۰۰ ردیف، WAL، Backup/Restore،
پرشدن دیسک، نصب تمیز، Build/Typecheck، Rollback و تولید گزارش‌های نهایی بوده است.

**تصریح مهم:** آزمون Soak واقعی ۲۴ و ۷۲ ساعته در این جلسه اجرا نشده است (زمان
اجرای جلسه محدود است). هارنس آن ساخته و با موفقیت در اجرای ۱۵۲ ثانیه‌ای اعتبارسنجی
شده است؛ اجرای ۷۲ ساعته باید روی سرور اختصاصی انجام و نتیجه به این گزارش ضمیمه شود.
بنابراین معیار «۷۲ ساعت بدون Crash» در وضعیت **در انتظار اجرا** است، نه PASS.

پنجره‌ها، رویدادهای Flap/هم‌زمانی/تایم‌لاین، موتور و کنترل آن، تنظیمات،
گزارش‌ها و خروجی، حسابرسی، سلامت/Checkpoint/Backup/Verify/Prune/Restore و SSE.

## ۶. تست‌های کلیدی این مرحله

- **دسترسی و نقش‌ها:** ۴۰۱ برای همهٔ APIهای محافظت‌شده، ۴۰۳ برای Viewer/Operator،
  آخرین Administrator قابل حذف/تنزل نیست، CSRF و Origin بیگانه رد می‌شود.
- **ورودی مخرب:** پسوند غیرمجاز، XLSX جعلی، MBTiles جعلی، Path Traversal در نام فایل،
  سقف ۱۰۰ ردیف (در تست)، JSON با `__proto__`، Content-Type نامعتبر، Queryهای بی‌معنا.
- **هم‌زمانی:** ۵۰ ثبت هم‌زمان، مسابقهٔ IP تکراری (۱ برنده، ۱۱ خطای منطقی، صفر ۵۰۰)،
  ۲۰ ویرایش هم‌زمان، حذف گروهی idempotent، خواندن حین نوشتن، Backup حین نوشتن.
- **موتور:** ۵ چرخهٔ قطع/وصل متوالی، هر چرخه دقیقاً یک Outage، بازگشت بدون رکورد
  باز، صفر خطای موتور؛ دو موتور هم‌زمان هر تجهیز را دقیقاً یک بار بررسی می‌کنند.
- **Crash/Recovery:** `SIGKILL` وسط نوشتن و وسط تراکنش، بازیابی WAL و ادامهٔ نوشتن.
- **شبکه:** ۸ قطع/وصل متوالی SSE با دریافت دوبارهٔ `hello` و حذف کامل کلاینت‌ها.
- **SSE:** ۱۰۰ اتصال هم‌زمان، دریافت `hello` برای همه، بستن تمیز، رشد RSS محدود.
- **WAL:** رشد در نوشتن پیوسته، Checkpoint از نوع TRUNCATE زیر ۵ ثانیه، کاهش WAL
  به ≤۶۴KB و حفظ کامل ردیف‌ها.
- **Backup/Restore:** پشتیبان WAL-سازگار، رد پشتیبان دست‌کاری‌شده، Dry-run،
  بازیابی کامل، پشتیبان ایمنی پیش از Restore.
- **دیسک پر:** ۵۰۷ پیش از نوشتن، Rollback کامل ورود گروهی، عدم باقی‌ماندن پوشهٔ ناقص.
- **Rollback:** بازیابی دادهٔ پیش از انتشار + اجرای آرشیو نسخهٔ قبلی + Build و
  پاسخ `200` برای صفحهٔ اصلی.

## ۷. محدودیت‌ها و کارهای باقی‌مانده

1. **Soak ۲۴/۷۲ ساعته:** اجرا نشده است. دستور:
   `npm run qa:soak72` (۱۰۰ تجهیز، بازهٔ ۳۰ ثانیه). خروجی JSON شامل RAM/CPU/دیسک/WAL،
   پیک و روند است. معیار قبولی: `ok=true` و `leakSuspected=false`.
2. **آزمون تعاملی مرورگر:** تست‌های UI در سطح منطق/تایپ و HTTP هستند؛ کلیک‌های
   دستی روی نقشه، فرم‌ها و نوار وضعیت باید توسط کاربر در پنل پیش‌نمایش تأیید شود.
3. **محیط بار:** ۲ vCPU / ۴GB. اعداد ۵٬۰۰۰ تجهیز برای این ظرفیت است؛ روی سخت‌افزار
   قوی‌تر بهتر و روی سخت‌افزار ضعیف‌تر بدتر خواهد بود.
4. **WAL در بار ۵۰٬۰۰۰ ردیف:** رشد موقت حافظهٔ سرور ۲۴۳MB مشاهده شد (پیک، نه نشتی)؛
   پس از اتمام کار آزاد می‌شود. برای سرورهای کوچک، ورود را در دسته‌های ۱۰٬۰۰۰ ردیفی
   انجام دهید.
5. **محدودیت‌های ذاتی امنیتی:** Rate Limit درون‌حافظه‌ای، نبود قفل حساب پس از
   تلاش ناموفق، و نبود UI برای مدیریت کاربران/حسابرسی (در `SECURITY.md` ثبت شده‌اند).

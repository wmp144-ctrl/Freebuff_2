## ۸. حسابرسی و عدم افشا

- `audit_log` شامل ورود/خروج، تغییر تنظیمات، مدیریت کاربران، حذف، Probe،
  خروجی‌گیری و درخواست‌های ردشده است؛ رمز/توکن ثبت نمی‌شود.
- `GET /health` عمومی فقط `{ok,status,ts}` است؛ مسیر DB، نسخه، موتور و آمار
  افشا نمی‌شود.
- خطاهای داخلی به پیام عمومی تبدیل می‌شوند و جزئیات فقط در لاگ ساختاریافته است.
- خروجی Backup فقط از طریق API مدیریتی و با بررسی مسیر مجاز است؛ Path Traversal
  در نام پشتیبان رد می‌شود.
- بازنشانی داده پیش‌فرض غیرفعال است (`NETWATCH_ALLOW_RESET=1` لازم است).

## ۹. یافته‌های این دوره

1. **پاسخ ۵۰۰ برای XLSX خراب** — اصلاح: نگاشت خطای پردازش فایل به ۴۰۰.
   Regression: `malicious.test.mjs`.
2. **از دست رفتن کد ۵۰۷ در ورود گروهی هنگام دیسک پر** — اصلاح: حفظ ۵۰۷.
   Regression: `disk-full.test.mjs`.
3. **پاسخ پیش‌نمایش بدون سقف برای ۵۰k ردیف** — اصلاح: نمونهٔ ۲۰۰ ردیفی +
   `truncated`. Regression: `import-50k.test.mjs`.
4. **احتمال ۵۰۰ برای MBTiles با هدر معتبر و محتوای خراب** — اصلاح: ۴۰۰.
   Regression: `malicious.test.mjs`.

هیچ یافتهٔ Critical/High در بازبینی این دوره باقی نمانده است.

## ۱۰. ریسک‌های باقی‌مانده (Low / عملیاتی)

1. **Rate Limit درون‌حافظه‌ای** است و با ری‌استارت صفر می‌شود؛ پشت چند نمونه،
   محدودیت باید در پروکسی/Ingress هم اعمال شود.
2. **قفل حساب پس از تلاش ناموفق** وجود ندارد؛ فقط Rate Limit IP و Audit.
3. **مدیریت کاربران و حسابرسی فقط API است**؛ UI گرافیکی ندارد. دسترسی به API
   با نقش Admin محدود است.
4. **Soak ۷۲ ساعته** هنوز اجرا نشده؛ ریسک نشتی بلندمدت به‌طور کامل رد نشده است.
   هارنس و معیار قبولی آماده است.
5. **زنجیرهٔ تأمین:** `xlsx` از tarball رسمی SheetJS نصب می‌شود؛ در محیط‌های
   سخت‌گیرانه، آینهٔ داخلی و بررسی SHA-256 بسته توصیه می‌شود.
